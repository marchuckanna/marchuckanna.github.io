# Портфолио на Markdown

Структура и оформление сайта сохранены. Работы, «Обо мне» и «Контакты» теперь редактируются в Markdown без правки JavaScript. EN — основной язык; переключение EN / RU сохраняет открытую страницу.

## Как это работает

При открытии сайт читает projects/index.json, затем Markdown-файлы и формирует страницы. На главной — только избранные работы; в категориях — все работы своей группы. Направление является свободным текстом и не участвует в фильтрации.

GitHub Pages не предоставляет браузеру список файлов в папке. Поэтому при каждом push GitHub Actions автоматически сканирует projects/, проверяет содержимое и создаёт каталог для опубликованной версии. Вам достаточно добавить папку работы и отправить изменения в GitHub. Сканирование папок происходит при публикации; сами Markdown-файлы браузер читает при открытии сайта.

## Структура

~~~text
projects/
  the-shape-of-silence/
    project.md          ← все параметры и тексты одной работы
    cover.svg           ← обложка
    detail.svg          ← дополнительная картинка
  forma/
    project.md
    cover.svg
    detail.svg
  ...
  _example/             ← готовый шаблон, не отображается на сайте
    project.md
    cover.svg
  index.json            ← автоматически создаётся при публикации
pages/
  about.md              ← одна картинка, биография, ссылки
  contact.md            ← тексты и ссылки контактов
assets/                 ← общие изображения
scripts/build-index.mjs ← проверка и создание каталога
.github/workflows/pages.yml ← публикация
~~~

Каждая непосредственно вложенная папка projects/ — отдельная работа, обязательно с project.md. Вложенные папки для изображений разрешены. Имена папок — строчные латинские буквы, цифры и дефисы: my-new-book. Имя папки становится идентификатором и адресом проекта; переименование изменит адрес. Папки с начальным _ или . игнорируются.

## Добавить работу

1. Скопируйте projects/_example/ в projects/my-new-book/.
2. Положите туда свои изображения: SVG, WebP, JPG, PNG или другой формат, поддерживаемый браузером.
3. Измените project.md по примеру ниже. Сохраните в UTF-8.
4. Сделайте commit и push. GitHub Actions автоматически добавит работу и опубликует сайт.

Обложка не обязана называться cover.svg — укажите своё имя в cover. Для растра обычно достаточно ширины 1200–1800 px и размера до 300–500 КБ. Превью кадрируется до 10:11; главное изображение на странице проекта видно целиком.

## Полный пример project.md

Готовая рабочая копия с изображением находится в projects/_example/.

~~~markdown
---
category: обложка
featured: true
order: 70
year: 2026
cover: cover.svg
demo: false
---

## title.en

The quiet atlas

## title.ru

Тихий атлас

## direction.en

Book cover · Travel essays

## direction.ru

Книжная обложка · Путевые эссе

## description.en

A cover for a collection of travel essays. **Colour and rhythm** evoke a place without showing it literally.

A second paragraph can describe the brief or your role.

## description.ru

Обложка сборника путевых эссе. **Цвет и ритм** передают ощущение места без буквального изображения.

Во втором абзаце можно описать задачу или вашу роль.

## concept.en

A restrained palette connects the cover to the inner pages.

## concept.ru

Сдержанная палитра связывает обложку с внутренними страницами.

## status.en

Commissioned project

## status.ru

Заказной проект

## gallery.en

![The full cover](cover.svg)

### Details

An explanation of this part of the project.

![Endpaper illustration](images/endpaper.webp)

## gallery.ru

![Обложка целиком](cover.svg)

### Детали

Пояснение к этой части проекта.

![Иллюстрация для форзаца](images/endpaper.webp)
~~~

В этом примере images/endpaper.webp — ваш файл: добавьте его или удалите строку до публикации. В готовом _example используются только существующие изображения.

### Параметры

| Параметр | Назначение |
| --- | --- |
| category | Обязательно: обложка, иллюстрация или дизайн. Определяет галерею и пункт меню. |
| featured | true — показывать на главной; false или отсутствие — только в категории. |
| order | Чем меньше число, тем раньше работа. По умолчанию 1000. При равенстве — по имени папки. Определяет и последовательность следующих проектов. |
| year | Необязательный год или диапазон, например 2025–2026. |
| cover | Обязательная обложка: путь от project.md или полный HTTP(S)-адрес. |
| demo | true — примечание о демонстрационном проекте; false или отсутствие — без примечания. |

В начале файла используется простой блок «ключ: значение», а не полный YAML: без вложенных объектов, массивов и многострочных значений. Все длинные тексты идут ниже. Служебные имена разделов (например ## title.en) менять не нужно.

### Текстовые разделы

Каждый раздел имеет .en и .ru версии в одном файле.

| Раздел | Назначение |
| --- | --- |
| title.en / title.ru | Обязательное название. Обычный текст. |
| direction.en / direction.ru | Обязательное направление, любая формулировка. Обычный текст, без фильтрации. |
| description.en / description.ru | Обязательное вводное описание. Markdown и несколько абзацев. |
| concept.en / concept.ru | Необязательный блок «Идея». Markdown. |
| status.en / status.ru | Необязательный статус: заказ, авторская работа и т. п. Обычный текст. |
| gallery.en / gallery.ru | Необязательная последовательность изображений, подзаголовков и текста. Markdown. |

Для обязательных разделов нужны оба перевода. Для необязательных, если один перевод пропущен, используется другой. Если оба пусты, блок скрывается. Количество изображений не ограничено, порядок определяется строками в галерее.

### Локальные и внешние изображения

~~~markdown
![Описание для доступности](detail.svg)

![Растр](images/process.jpg)

![Внешнее изображение](https://example.com/portfolio/project.webp)
~~~

Последний адрес — пример, замените реальной прямой ссылкой на изображение. Ссылка на страницу Behance или Google Drive не является прямой ссылкой на картинку. Предпочитайте HTTPS: HTTP-картинки могут блокироваться на HTTPS-сайте. Внешний сервер должен разрешать показ изображения. Для надёжности храните работы в репозитории.

Пути считаются от Markdown-файла. В pages/about.md путь ../assets/sunday.svg ведёт в общую папку. Начальный / не поддерживается, чтобы работали подпапки и собственный домен. Избегайте пробелов и скобок в именах или кодируйте их как %20, %28, %29.

### Поддерживаемый Markdown

- Абзацы разделяются пустой строкой; перенос внутри абзаца тоже отображается.
- **Полужирный** записывается как **текст**, курсив — как *текст*.
- Код между обратными кавычками.
- Подзаголовки ### Заголовок, отделённые пустыми строками.
- Списки с - Пункт или 1. Пункт.
- Цитаты с > Текст.
- Ссылки [Название](https://example.com) и email [Написать](mailto:name@example.com).
- Изображения ![Описание](image.webp).

Это небольшой Markdown-формат: HTML, таблицы, вложенные списки и сложное вложенное форматирование не обрабатываются. HTML выводится текстом, небезопасные протоколы ссылок отклоняются.

## «Обо мне» — pages/about.md

| Поле или раздел | Назначение |
| --- | --- |
| image в блоке --- | Одна картинка: локальный путь или HTTP(S)-адрес. |
| title.en / .ru | Обязательный заголовок страницы. |
| eyebrow.en / .ru | Небольшая надпись над ним. |
| heading.en / .ru | Крупный заголовок рядом с картинкой. Поддерживает переносы и курсив. |
| description.en / .ru | Обязательная биография в Markdown. |
| caption.en / .ru | Подпись и альтернативное описание картинки. |
| links-title.en / .ru | Название блока ссылок. |
| links.en / .ru | Ссылки в Markdown-списке. |
| summary-heading.en / .ru | Заголовок блока «Обо мне» на главной. |
| summary.en / .ru | Его текст на главной. Markdown. |

Например, замените существующий блок ссылок:

~~~markdown
## links.en

- [Behance](https://www.behance.net/YOUR-PROFILE)
- [Email](mailto:YOUR-EMAIL@example.com)

## links.ru

- [Behance](https://www.behance.net/YOUR-PROFILE)
- [Написать](mailto:YOUR-EMAIL@example.com)
~~~

Замените примерные адреса своими. Внутренние ссылки из pages/ имеют вид ../?page=illustration; для русского языка — ../?page=illustration&lang=ru.

## «Контакты» — pages/contact.md

Страница полностью состоит из текста. Оставьте начальный блок --- с комментарием; параметры в нём не требуются.

- eyebrow.en / .ru — надпись над заголовком.
- title.en / .ru — обязательный заголовок; поддерживает перенос строки и курсив.
- description.en / .ru — обязательный вводный текст.
- details.en / .ru — левая колонка: контакты, ссылки, любой текст.
- briefing.en / .ru — правая колонка: пожелания к запросу, языки общения, любой текст.

Например, вместо текущей заглушки:

~~~markdown
## details.en

### Write to me

[YOUR-EMAIL@example.com](mailto:YOUR-EMAIL@example.com)

[Behance](https://www.behance.net/YOUR-PROFILE)

## details.ru

### Написать мне

[YOUR-EMAIL@example.com](mailto:YOUR-EMAIL@example.com)

[Behance](https://www.behance.net/YOUR-PROFILE)
~~~

## Локальный просмотр

В Windows дважды щёлкните **preview.cmd** в корне сайта. Он запустит сервер и откроет http://127.0.0.1:8080/ в браузере. Node.js, Python и установка зависимостей не нужны. Не закрывайте окно сервера во время просмотра; Ctrl+C останавливает его.

Запуск использует `-ExecutionPolicy Bypass` только для отдельного процесса локального сервера, чтобы стандартный запрет PowerShell на `.ps1` не блокировал просмотр. Системные и пользовательские настройки политики не меняются; выполнять `Set-ExecutionPolicy` не требуется.

Сервер автоматически определяет папки проектов при каждом обновлении страницы, поэтому вручную менять projects/index.json для этого способа просмотра не нужно. Измените Markdown или добавьте папку проекта и обновите страницу браузера.

Если порт 8080 уже занят, запустите из PowerShell в корне сайта:

~~~powershell
.\preview.cmd -Port 8081
~~~

Сервер доступен только на этом компьютере (127.0.0.1). Открытие index.html двойным кликом через file:// не работает: браузер запрещает fetch читать соседние Markdown-файлы. Сайт покажет подсказку о preview.cmd.

Альтернатива — Live Server в VS Code. При этом способе после добавления или удаления папки проекта обновите каталог командой node scripts/build-index.mjs (нужен Node.js 22+) либо измените projects/index.json вручную. На GitHub каталог всегда пересоздаётся автоматически.

## Публикация

Однократно: Settings → Pages → Build and deployment → Source → **GitHub Actions**. Это заменяет прежнюю публикацию из ветки: теперь нужен автоматический каталог.

1. Сделайте commit и push в main или master.
2. Во вкладке Actions дождитесь успешного **Publish portfolio**.
3. Откройте https://marchuckanna.github.io/.

Если основная ветка другая, измените branches в .github/workflows/pages.yml. Ручной запуск — Actions → Run workflow.

При ошибке Markdown, отсутствии картинки или обязательного перевода новая версия не публикуется; причина будет в журнале Actions. Доступность внешних картинок автоматически не проверяется.

Для собственного домена задайте его в Pages и сохраните CNAME в корне репозитория: workflow перенесёт его в публикацию. Все пути относительные.

## Удаление и черновики

- featured: false убирает работу только с главной.
- Для удаления с сайта удалите папку или добавьте начальный _, затем сделайте push.
- Workflow исключает папки с _ из опубликованных файлов. Это не защита данных: в публичном репозитории исходники доступны, а история Git и старые публикации могут хранить удалённые материалы.

Текущие проекты имеют demo: true. Для реальной работы поставьте demo: false. Общая демо-подпись в футере исчезнет, как только появится реальная работа.

## Техническая проверка

Нет npm-зависимостей. content.js — общий парсер для браузера и проверки публикации. app.js загружает контент и сохраняет прежнюю композицию. Старый projects.js удалён, тексты работ не дублируются в коде. Постоянные подписи интерфейса и вводный заголовок главной остаются в app.js; работы, биография, её блок на главной и контакты — в Markdown.

~~~sh
node scripts/build-index.mjs
node --test tests/content.test.cjs
~~~

Тесты проверяют обе языковые версии, маршруты всех проектов, избранное, категории, кнопку меню, форматирование и протоколы ссылок. Проверки учитывают будущие изменения текстов и добавление проектов.
