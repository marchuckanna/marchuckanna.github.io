# Anna Marchuk — portfolio

Готовый статический прототип для GitHub Pages: HTML, CSS и JavaScript без npm и сборки. Основной язык — английский; переключатель EN / RU сохраняет текущую страницу и проект. Все шесть работ — оригинальные демонстрационные SVG-концепции, а не реальные заказы.

## Просмотр

Откройте `index.html` в браузере. Для просмотра через локальный сервер можно использовать расширение Live Server в VS Code. Интернет нужен только для необязательных Google Fonts; системные шрифты работают без сети. Сам сайт, изображения и навигация не зависят от внешних сервисов.

Страницы имеют постоянные адреса: `?page=book-covers`, `?page=illustration`, `?page=graphic-design`, `?page=about`, `?page=contact`, `?page=project&project=forma`. Добавление `&lang=ru` открывает русский перевод. Такие адреса работают на GitHub Pages без серверного роутинга и 404 при обновлении.

## Личные данные и контакты

В `projects.js` задайте `email: 'your-real-address@domain.com'` и ссылки в `socials`, например `{ label: 'Behance', url: 'https://www.behance.net/your-profile' }`. Пока контакты не заполнены, сайт честно показывает «Контакты скоро появятся» и не предлагает фиктивных адресов. Имя и биографию при необходимости измените в `app.js` (английская и русская версии). Поле `name` в `projects.js` оставлено для справки, отображаемое двуязычное имя задаётся в `app.js`.

## Замена изображений и добавление работ

1. Поместите свои изображения в `assets/`. Предпочтительны WebP или JPG шириной 1200–1800 px, до 300–500 КБ. Не включайте важные детали у краёв превью: миниатюра имеет пропорцию 10:11 и использует `object-fit: cover`. На странице проекта изображение видно целиком.
2. Откройте `projects.js` и замените `image` у нужного проекта. Необязательное `detail` — дополнительное широкое изображение. Самый быстрый способ сохранить композицию — заменить SVG-файл по тому же пути, но для фотографий поменяйте также расширение в данных.
3. Для новой работы скопируйте объект в массив `projects`. Задайте уникальный `id` латиницей через дефис, категорию `book-covers`, `illustration` или `graphic-design`, год, изображения и тексты.
4. Двуязычные поля `title`, `type`, `description`, `concept` — массивы `["English", "Русский"]`. `description` — вводное описание, `concept` — идея проекта. Порядок объектов определяет порядок работ на главной и ссылку следующего проекта.
5. После замены демо на реальные проекты обновите обозначение концепций в `app.js`: метаданные проекта, примечание `.demo-note`, подпись под избранными работами и подпись в футере. Сейчас эти обозначения намеренно защищают от восприятия демо как реальных заказов.

## Публикация на GitHub Pages

1. Добавьте файлы в коммит и отправьте в основную ветку репозитория `marchuckanna.github.io`.
2. В GitHub откройте **Settings → Pages → Build and deployment**, выберите **Deploy from a branch**, ветку `main` (либо фактическую основную ветку) и каталог **/ (root)**, затем **Save**.
3. После завершения публикации сайт будет доступен по адресу `https://marchuckanna.github.io/`. Файл `.nojekyll` отключает ненужную обработку Jekyll.

Для собственного домена укажите его в **Settings → Pages → Custom domain**, настройте DNS по инструкции GitHub и включите **Enforce HTTPS** после выпуска сертификата. GitHub создаст `CNAME`; сохраните его в репозитории. Все ресурсы используют относительные пути и поддерживают собственный домен, а также публикацию в подпапке.

## Файлы

- `index.html` — входная страница и метаданные.
- `style.css` — адаптивная сетка, типографика и состояния элементов.
- `projects.js` — данные, переводы проектов и контакты.
- `app.js` — страницы, навигация и переводы интерфейса.
- `assets/` — оригинальные векторные демонстрационные работы.

Внешние тексты внутри демонстрационных иллюстраций — часть авторского макета, поэтому они не меняются при переключении языка. Интерфейс, метаданные проекта и описания переведены полностью. Перед профессиональным запуском дополните реальными контактами и работами, проверьте имя, биографию и социальные ссылки.
